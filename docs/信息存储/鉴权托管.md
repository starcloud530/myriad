# 鉴权托管

万象第一期**没有自建密钥库**。平台自有的厂商 Key 租用 Cloudflare Workers Secrets；租户自己的上游 Key（BYOK）是第二期才做的事。

## 两种 Key，不要混

### 南向：厂商 Key

DeepSeek / 千问 / fal / 火山这四把 Key 是平台资产。

- **值不进数据库、不进 yaml、不进 catalog、不进 git。**
- catalog / `channel.config` 只记变量名，例如 `secret_env: "DEEPSEEK_API_KEY"`。适配器读 `env[secret_env]`。
- 本地开发：把 `现有服务厂商模型/.env` 里的同名变量拷到 `packages/gateway/.dev.vars`（gitignore，和 `.env` 同类）。`wrangler dev` 注入 `env`。
- 上线：`wrangler secret put DEEPSEEK_API_KEY`（以及另外三把）。值进 Cloudflare 账号 Secrets，运行时同样是 `env.DEEPSEEK_API_KEY`。
- `.dev.vars` **不同步**。第二台电脑、第二个同事、另一个 Worker 项目都看不见。线上同一 Worker 的全球 isolate 共享同一套 Secrets，由 CF 分发。
- 两个不同的 Worker 默认不共享 secret。南向 Key 只放在 `@myriad/gateway`。

对外 `GET /v1/capabilities` 必须剥掉 `channel.config`，前端永远拿不到变量名背后的值。

### 北向：产品 Key

下游打万象的令牌。

- 控制台：HttpOnly session cookie（Google / GitHub；本地另有 `POST /v1/auth/dev/session`）。身份和租户在 D1，与用量账本同一库。
- 种子：`catalog/seed.ts` 的 `dev-key` **仅本地**。生产 `MYRIAD_ENV=production` 时网关不认、catalog 也不再挂这把钥匙。
- SDK / CLI：`Authorization: Bearer sk-…`，Key 属于登录时自动创建的租户。
- 控制台签发：`POST /v1/keys`（cookie 或该租户的 Bearer），明文只回一次；哈希进 `MYRIAD_KEYS` KV。
- 这不是厂商 Key，对标令牌表，不是 Dify 的 `provider_credentials`。
- 教程见 [docs/keys.md](../keys.md)。

## 为什么不抄 Dify 进 D1

Dify 把租户自己贴的 OpenAI Key 当业务数据：RSA+AES 加密写入 `provider_credentials.encrypted_config`。那是「N 个租户、N 把别人的 Key」。

万象第一期只有四把平台自有 Key。Cloudflare Secrets 已经是平台级密钥库（注入 `env`、网页不回传明文、含在 Worker 套餐里）。再自建一套解密/轮转是重复劳动。

第二期若做租户 BYOK：密文进 D1，主密钥 `BYOK_MASTER_KEY` 仍放 CF Secrets，控制台只回显 mask。那是另一张表，不挡第一期四能力。

## 变量名（第一期）

| 渠道 | `secret_env` | 本地 | 上线 |
|---|---|---|---|
| DeepSeek | `DEEPSEEK_API_KEY` | `.dev.vars` | `wrangler secret put` |
| 千问 | `QIANWEN_API_KEY` | 同上 | 同上 |
| fal | `FAL_API_KEY` | 同上 | 同上 |
| 火山 | `VOLCENGINE_API_KEY` | 同上 | 同上 |

代码只认 `env[...]`，不读 yaml、不读 `现有服务厂商模型/.env`。
